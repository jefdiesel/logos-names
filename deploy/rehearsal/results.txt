== Failures found and fixed ==========================================================
1. boot: kit up.sh imports the test key with `--private-key`; v0.4.0 wallet wants `--secret`.
   Fixed by hand on the VM (kit file, not in this repo).
2. boot: kit chain.sh writes `cross_zone` into the sequencer config; v0.4.0 has no such
   field. Fixed by hand on the VM: `c.pop("cross_zone", None)`.
3. fund: v0.4.0 prints a public key as `initial key <hex>` and takes `--to-initial-key`
   (rc3: `pk` / `--to-pk`); and the names CLI ignores the wallet config's sequencer and uses
   LOGOS_NAMES_RPC (default: the public testnet), so every wallet call timed out after 60 s.
   Fixed in deploy.sh + rehearse.sh (both key forms parsed; RPC exported before any wallet call).
4. deploy: rehearse.sh's params rewrite hit `[confirmed_by_jef]` keys of the same name
   (rpc_url, admin, ...) instead of `[network]`/`[accounts]`. Fixed: section-aware rewrite.
5. configure-nft: the sequencer's r0vm was 3.0.3; v0.4.0 uses risc0-zkvm 3.1.0
   ("r0vm server is not compatible"). Fixed on the VM: `rzup install r0vm 3.1.0`.
   The Mini's guarded r0vm is 3.0.5: it needs 3.1.0 too (RUNBOOK checklist).
6. verify: deploy.sh read the price table as `5`/`6-7`/`8+`; the CLI prints `tier_5`/
   `tier_6_7`/`tier_8_plus`. On-chain prices were right. Fixed: both key forms accepted.
7. post-deploy: the resolve JSON has `held_by`, not `account`; the smoke picked the
   wallet's first (unfunded) account. Fixed: `held_by` read, `smoke_public_owner` used.
